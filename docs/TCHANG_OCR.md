# T창 캡처 인식 (OCR) — 구조와 이어서 할 일

2026-09-29 기준. 전투력 탭 "캡처로 채우기" / 입력칸 밖에서 Ctrl+V.

## 흐름

| 단계 | 코드 | 내용 |
|---|---|---|
| 창 위치 | `tchangOcr.locatePanel` | 고정 라벨 이미지(좌 "크리티컬 확률"·"몬스터 지배력", 우 "근력/마법력 효율"·"직접 타격")를 NCC 패턴 매칭. 두 라벨 간격으로 배율 `s` 추정 (흐리거나 1~5% 늘어난 캡처 대응) |
| 칸 자르기 | `LAYOUT`, `planCells`, `mapBox` | 샘플 캡처(684×576) 좌표 → 캡처 좌표. 캐릭터 타입 쪽 칸만 (백어택·효율은 물리·마법 둘 다 — 서로 확인용) |
| 확대·전처리 | `cropUpscale` → `cellGray` → `sharpenGray` → (`spaceDigits`) | 직접 구현한 bicubic 확대라 브라우저·테스트 결과가 같다. 짧은 정수 칸(관통력 등)은 붙은 숫자("99")를 떼어 놓는다 |
| 숫자 읽기 | `useTchangOcr` (Tesseract.js eng, psm 7) | `READ_VARIANTS` 조합으로 최대 7번 읽고 다수결(`vote`). 앞 3번이 같으면 멈춤 |
| 검증 | `crossCheck` · `resolveCross` · `sanityFlags` | 표시값 ≈ 기본 × (100+%)/100 대조 → 안 맞으면 다른 후보·비슷한 숫자(1↔7, 3↔9 …) 치환으로 보정. 최소/최대 비율, 백어택·효율 물리=마법 확인 |
| 확인 표 | `TchangImportDialog.vue` | 캡처 조각 · 인식값(수정 가능) · 현재값. 흔들림·검증 실패는 기본 해제. **전투력 검산**: 읽은 값으로 계산한 직접·소환 전투력 vs T창 (±0.15%) |

- 라벨 이미지: `src/data/tchangTemplates.json` ← `node scripts/build_tchang_templates.mjs` (샘플 `tests/fixtures/tchang-sample.png`)
- Tesseract.js·eng 데이터는 붙여넣을 때만 CDN 에서 받는다 (Apache-2.0). 이미지는 브라우저 밖으로 나가지 않는다.

## 정확도 (캡처 5장, 입력 25항목씩)

| 캡처 | 정확 | 비고 |
|---|---|---|
| `tchang-sample.png` (원본) | 25/25 | 검산 통과 |
| `tchang-sample2.png` (원본, 예시 캐릭터) | 24~25/25 | 근마효율 37→3 이 가끔 — 효율 확인으로 해제됨 |
| `tchang-p3/p4/p5.png` (흐림·1~2% 늘어남) | 24 / 19 / 24 | 틀린 값 대부분 해제 또는 검산 불일치 경고 |

조합(`READ_VARIANTS*`)은 위 5장 × 108조합 격자 탐색으로 골랐다. 캡처가 늘면 다시 탐색할 것.

## 알게 된 게임 규칙

- **종합 전투력 = 물리·마법 중 높은 쪽** (근력≈마법력 캐릭터는 마법 평균이 종합으로 표시됨). 직접·소환 전투력은 T창 오른쪽 위에 물리·마법 각각.
- 기본 무기공 폭이 15 미만이면 무기공 범위가 **역순**으로 표시된다 (예: 52,179 ~ 52,169) — `parseValue('range')` 가 허용.
- 최소 대미지가 최대보다 큰 캐릭터가 있다 (7,605 / 7,278) — 전투력은 min(최소, 최대) 로 캡.

## 이어서 할 일

1. 캡처가 늘면 `tests/fixtures/` 에 추가하고 정답을 넣어 조합 재탐색 (scratchpad 의 grid 스크립트 방식 — 확대는 반드시 `cropUpscale`).
2. 마법 캐릭터 캡처로 검증 (지금 fixture 는 전부 물리).
3. 전투력 공식: 새 물리 캐릭터 5명 기준 직접 ±0.03%, 소환 ±0.08% 오차. 물리 소환 계수 재적합 후보(무공 항 −0.4%)가 있지만
   흐린 캡처 기준이라 보류 — 원본 해상도 통제 캡처(무기만/근력만/크댐만 바꾼 전후)로 확정할 것.
