### 공식 뼈대 (직타 기준)

```
B_0 = 주스탯_eff + floor(무기난수 × (스킬계수 + 100) / 50)
m   = f32(1 − DEF / (DEF + a) × (100 − PEN) / 100)      a = 물리 30L+200 / 마법 20L+200
B_1 = f32(f32(B_0) × m)
B_2 = f32(B_1 + 고정대미지 + 추가대미지)
U   = f32(B_2 − 피해감소)
K   = 100 + (크리면 floor(크댐 × (1000 − 크리저항) / 1000)) + 백어택/근거리/상태이상
T   = floor(f32(U × f32(K/100)) × Q / 100)               Q = 최소~최대 대미지 난수
최종 = floor(T × (100 − Guard) / 100 × f32(1 + f32(지배력/100)))
```

- **f32(단정도) 변환과 floor 위치가 값에 영향을 준다.** 순서를 바꾸면 몇 % 어긋난다.
- 난수가 둘(무기 W, 대미지 Q)이라 결과는 범위다. UI 는 min / mid / max 를 모두 보여준다.
- 소환은 기본 공격값·크댐·조건부가 다르다: 능력치 효율(EFF) 미적용, 관통은 **표시값 무시하고 실효 99%**,
  백어택은 캐릭터 값 대신 **고정 +20**, 근거리·상태이상 미적용.

### T창 → 공식 입력 매핑에서 내린 결정

공식은 `raw 고정값 + 최종 %` 로 나눠 받지만 T창은 이미 합쳐진 표시값을 준다.
그래서 **표시값을 raw 로 넣고 F=0** 으로 둔다. 굳이 쪼개면 floor 가 한 번 더 끼어 값이 달라진다.
단, "최종 크리티컬/최소/최대 대미지" 처럼 T창 밖에서 곱해지는 옵션은 UI 에서 따로 입력받는다.

## 3. 검증되지 않은 것 (= 다음 할 일)

### 3.1 실측 대조 — 가장 먼저 할 일

**목각인형 프리링**은 방어력·저항력·피해감소·Guard·크리저항이 **전부 0**이다.
피격자 측 항이 통째로 사라지므로 공식 검증의 기준점으로 쓴다.

필요한 측정 데이터(한 건당):

- 캐릭터 T창 스탯 전체 (주스탯, 무기공격력 표시범위 두 값, 크댐, 최소·최대 대미지, 고댐, 일/보몬추, 지배력, 관통, 근마효율)
- 캐릭터 레벨
- 쓴 스킬 이름·레벨과 그 **스킬 계수** (툴팁 표기)
- 대상 (목각인형 프리링 권장)
- 실제 나온 대미지 — **크리/비크리 구분**, 여러 번 때려 **최솟값·최댓값**

검증 순서:

1. 목각인형으로 비크리 최소·최대가 `damageRange().min/max` 와 맞는지 본다.
   → 여기서 맞으면 기본 공격값·난수·지배력 해석이 옳다.
2. 같은 대상 크리로 `K = 100 + 크댐` 해석을 확인한다.
3. **일반형 강철인형 머슬링**(방어력 2,187,171 / Guard 53 / 크리저항 600)으로
   방어 계수·Guard·크리저항까지 확인한다.
4. 맞으면 그 케이스를 `tests/damageFormula.test.js` 에 기대값으로 박아 회귀 테스트로 굳힌다.
   (지금 테스트는 구조만 검사하고 절대값은 검사하지 않는다.)

### 3.2 스킬 계수 연결

지금은 스킬 계수를 **손으로 입력**한다. 저장소에는 이미
`src/data/directHitSkills.js`(직타), `src/data/installerSkills.js`(설치·소환) 가 있으니
직업·스킬·레벨을 고르면 계수가 자동으로 채워지도록 연결하면 된다.
소환의 `S`(능력치 배율 %)·`SC`(공격력 계수)가 이 DB 에 있는지는 확인하지 않았다.

### 3.3 아직 안 본 것

- 몬스터 프리셋 수치 자체의 정확성 (전부 `verified: false`)
- 난이도 보정표가 실제와 맞는지
- 소환 실효 관통 99%가 모든 경우에 맞는지 (문서도 "검증된 범위에서는" 이라고 단서를 달았다)
- `R_min ∈ {1, 2}` — 방어 초과 시 1인지 2인지. 지금은 1로 고정
- 캐릭터 레벨 기본값 235가 맞는지 (프리셋 몬스터가 레벨 235라 그렇게 뒀다)

## 4. 검증이 끝나면 할 수 있는 것

1. **기존 대미지 예측 탭 대체** — `src/utils/damagePredict.js` 는 "대미지 ≈ C × BP × 스킬계수" 근사에
   사용자 캘리브레이션 C 가 필요하다. 이 공식은 캘리브레이션 없이 절대값을 낸다.
2. **스펙업 방향 분석 정밀화** — 지금은 "최종 크리티컬 대미지는 크리 확률 100% 가정" 같은 근사를 쓴다
   (`src/utils/statEquivalence.js` 의 `convertFinalOption`). 이 공식이면 대상·크리율을 넣은 실제 기대 대미지로 비교할 수 있다.
3. **BP 환산의 검증** — BP 식(`battlePower.js`)이 이 공식의 평균 근사와 맞는지 대조.
   특히 소환 크댐 계수 0.0148이 소환식 `(rawCD−50)×S/100+50` 의 어떤 S 에 해당하는지 확인.

## 5. 이어받는 세션에게

- 엔진은 순수 함수라 `node -e` 로 바로 돌려볼 수 있다. UI 없이 값만 확인하는 게 빠르다.
- 값이 안 맞을 때 의심 순서: ① f32/floor 위치 → ② 표시값 vs raw 해석 → ③ 스킬 계수 → ④ 몬스터 수치
- `npm test` 에 구조 테스트가 있으니 엔진을 고치면 먼저 돌린다.
- 프로젝트 규칙: 브랜치 만들지 말고 `main` 에 바로 커밋·푸시. UI 세부는 묻지 말고 기존 톤(한 줄 설명 + 접기, cyan 단일 포인트)에 맞춰 진행.
